# AI 在采购工作中的应用 — 理论内容

本文档是学习平台的"理论"部分，分为六章，对应实验室的六个 Lab 和上面的六个视频。建议先看视频，再做 Lab，然后回来看理论。这里写的是"为什么"——为什么这些概念存在，为什么对你的日常工作有用。

每章控制在十分钟以内可以读完。不需要任何编程背景。

整套体系是有层次的：API 是地基，MCP 和技能（Skills）在 API 之上扩展模型的能力，子代理和多代理编排把这些组合成工作流，评估（Evals）是验证整个系统真的在工作的方式。读完六章，你应该能看清这是一套完整的体系，不是六个孤立的工具。

---

## 第一章：API — 软件之间的对话

### 什么是 API

API 的全称是 Application Programming Interface（应用程序接口）。听起来很抽象，但实际上非常简单：**API 就是一个程序与另一个程序"对话"的标准方式**。

对我们的工作来说，可以这样理解：你日常每天都会做的事——查询当天的钢材价格、查询人民币对美元汇率、登录供应商网站抓取报价——这些信息其实都来自某个数据库或某个网站的服务器。如果你写一个程序，让它直接去问那个服务器要数据，跳过浏览器、跳过手动复制粘贴，那你用的就是 API。

AI 模型（Claude、DeepSeek、Qwen）也是通过 API 提供服务的。你发给它一段文本，它返回一段文本。**就这么简单——文本进，文本回**。

### 为什么这对采购工作很重要

想象你每天早上要做这几件事：

- 看一眼今天的钢价
- 查一下汇率，把昨天收到的几份美元报价换算成人民币
- 看几个新供应商的资料

如果这些数据都有 API，你写一个十行的脚本，几秒钟就能拿到结果，不用打开十几个网页。这就是 API 的力量——**把"手动重复的工作"变成"程序自动做的工作"**。

而且，所有更高级的 AI 工具——包括我们要学的 MCP、技能、子代理——本质上都是在组织一系列 API 调用。理解了 API 这个最基础的概念，后面的东西就不再神秘了。

### 一个具体的例子

我们采购钢材，每天会关心 LME 上的钢材价格，尤其是 FOB 中国的热轧卷板价格。有一些金属价格服务（比如 Metals-API）提供免费的 API：你去网站注册一个账号，拿到一个 API key（密钥，相当于一个"通行证"），然后用几行 Python 代码：

```python
import requests
response = requests.get("https://metals-api.com/api/latest?access_key=你的密钥&symbols=STEEL-HR")
print(response.json())
```

跑一下，几秒钟，今天的钢价就出来了。这就是一次 API 调用——你跟它说"给我今天的钢价"，它返回结构化的数据。

这跟你直接打开 Claude Code 输入一个问题、它给你回答，本质上是同一件事。Claude Code 也是软件，它在帮你打包问题、调用 AI 模型的 API、把答案显示给你。

### 一个关键点：我们的设置

我们的 Claude Code 后端连的是 DeepSeek 模型，不是 Anthropic 的 Claude 模型。这一点非常重要：**对你来说，体验是一样的**——打字、回车、看回答。但底层每一次调用都是发到 DeepSeek 的端点。所有后面要讲的概念（MCP、技能、子代理），机制上都在 API 之上，所以都能工作；但 AI 的"判断力"取决于后面的模型本身。

### 它跟后面几章的关系

- API 是地基
- MCP（下一章）是给 AI 标准化地访问外部 API 的方式
- 技能、子代理、编排，都是组织 API 调用的不同方式
- 评估，是检查这些 API 调用真的产出了正确结果

## 第二章：MCP — 给 AI 装上"双手"

### 什么是 MCP

MCP 的全称是 Model Context Protocol（模型上下文协议），是一个**开放标准**，让 AI 模型可以连接到外部的工具、数据源和服务。

最容易理解的比喻：**MCP 就是 AI 世界的 "USB-C"**。以前每个设备都需要自己专门的接口和线，乱七八糟；后来 USB-C 出来了，一个标准接口连所有东西。MCP 之于 AI 也是同样的逻辑——以前每个 AI 应用想接一个工具都要单独写一套代码；现在有了 MCP，一次写好，任何兼容的 AI 都能用。

### 没有 MCP 的 AI 是什么样

没有工具的 AI 只能"说话"。它能写报告、能翻译、能解释概念，但它**不能查今天的钢价、不能读你的报价文件、不能登录供应商网站**。它生活在自己的"对话框"里，与外部世界隔绝。

MCP 解决的就是这个问题——它给 AI 装上了"手"。

### 为什么对我们特别重要

MCP 是**开放标准，不是某一家公司的专有技术**。OpenAI、Google、Microsoft、AWS 都已经支持了。这意味着：**无论我们的 Claude Code 后面是 Claude 还是 DeepSeek，MCP 都能工作**。我们的设置完全兼容。

### 几个对采购有用的 MCP 工具

不是越多越好。一般来说，连接 2-3 个最常用的工具就够了，超过 5-7 个反而会让 AI 的表现变差（它要选的工具太多，反而拿不准用哪个）。

对我们的工作，几个起步推荐：

- **文件系统工具**（Filesystem）——让 AI 能读你电脑某个文件夹里的报价 PDF、规格书、图纸
- **网页搜索工具**（比如 Brave Search）——让 AI 能查询当天的市场行情、潜在新供应商
- **浏览器自动化工具**（Playwright）——让 AI 能登录供应商网站、抓取没有 API 的价格信息（比如直接打开 1688.com 搜索）
- **数据库工具**（如果你们的供应商或历史价格存在数据库里）——让 AI 直接查询

### 自己造一个 MCP 工具

如果你们有内部系统（自己的 ERP、内部询价单系统、内部价格表），可以把它包装成一个 MCP "服务器"，让 AI 通过统一的标准接入。但**绝大多数情况下不需要自己造**——网上已经有一万多个公开的 MCP 服务器，覆盖了几乎所有常见工具。

### 安全和注意事项

公网上的 MCP 服务器质量参差不齐——2026 年的一份安全调查发现，超过一三分之一的公开服务器存在严重的安全漏洞，超过四成根本不要求任何身份验证。所以：

- **先看源头**——别人写的工具，先看 GitHub 上有没有持续维护、有没有真实的贡献者
- **最小权限**——能给只读就别给读写，能限定一个文件夹就别给全盘访问
- **重点关注危险工具**——文件系统、数据库、能写入的工具，一律先用只读模式

### 它跟后面几章的关系

- **MCP 是"手"（工具）**
- **技能是"方法"（流程）**——技能告诉 AI 怎样按你的方法去使用这些 MCP 工具
- **子代理是"工人"**——它在自己的上下文里使用技能和 MCP 工具，完成专门化的任务

## 第三章：技能（Skills）— 把你的方法写下来一次

### 什么是技能

一个**技能（Skill）**就是一个文件夹，里面有一个说明文件（SKILL.md），可能还有几个脚本。它告诉 AI：**面对这一类任务时，请按这个方法做**。

把它想象成一份"标准操作手册"——你把你处理某个采购任务的最佳方法写下来一次，然后任何人在 AI 上触发这个技能，都能得到同样规范的输出。

### 没有技能时是什么样

没有技能，你每次跟 AI 解释一个任务，都要从头讲一遍："请帮我做一份比较表，列要有供应商、单价、币种、换算后的美元单价、交货天数……" 而且每次产出的格式都有微小差异，因为 AI 每次理解你的话都略有不同。

**技能的核心价值就是把这种"重复解释"和"格式漂移"一次性解决**。你写好一个技能，"做比较表"这个任务从此以后**每次的输出格式都一模一样**，任何团队成员调用都一样。

### 关键设计：技能可以包含脚本

这是技能最强大的地方。一个技能不只是文字指令——**它可以打包 Python 脚本**。任何需要精确计算或固定格式的部分，都可以放在脚本里，由代码执行。

为什么这对我们特别重要？因为我们的 Claude Code 后端是 DeepSeek。AI 模型本身的"心算"——比如重量计算、币种换算——在不同模型上准确度不一样。**但脚本是代码，代码运行结果是确定的，跟后面是什么模型无关**。

所以原则是：**任何必须精确的逻辑（计算、格式化、数据提取的结构），都放在脚本里；让 AI 模型只负责"判断"，不负责"算数"**。

### Anthropic 官方技能

Anthropic 在 GitHub 上公开发布了一批官方技能，可以免费下载、免费使用：

- **docx** — 创建、编辑、读取 Word 文档
- **xlsx** — 创建、编辑、读取 Excel 表格（带真实公式）
- **pdf** — 创建、填写、读取 PDF
- **pptx** — 创建 PowerPoint 演示文稿

这四个覆盖了 90% 的办公文档工作。它们都已经把所有"麻烦事"（格式、公式、样式）打包成了脚本，**用上去就是真实的、可以发给客户或同事的文档**。

下载方法在 Lab 3 里有详细步骤。

### 一个具体的例子

你想给江苏的某家钢材供应商发一份正式询价函，要 50 吨 A516 Gr70 钢板（12mm 厚）的报价。没有技能时，你会让 AI 写一段询价函的文字。

有了 docx 技能，你只需要说"用 docx 技能给江苏 XX 公司生成一份正式询价函，材料是 ...... 包含单价、交货期、国际贸易术语、付款条件"——AI 会调用 docx 技能里的脚本，生成一份真正的 .docx Word 文件，**直接可以发给供应商，不用再用 Word 排版**。

而且每次格式都一样。

### 它跟其他几章的关系

- **MCP 给 AI 工具，技能给 AI 方法**——一个技能可以告诉 AI "按这个顺序使用这些 MCP 工具"
- **子代理可以装备技能**——一个专门做某件事的子代理（下一章），可以内置一个技能让它做得始终一致

## 第四章：子代理（Subagents）— 专门化的助手

### 什么是子代理

**一个子代理就是一个"专门做某件事"的助手**，预先定义好——它有自己的指令、自己的工具权限、自己独立的上下文窗口。你按名字调用它，它专注做它那一件事，然后把结果交回给你。

### 为什么需要子代理

当一个 AI 试图什么都做的时候，它的"注意力"会分散，行为会变得不稳定——一会儿帮你写询价函，一会儿帮你做计算，一会儿帮你研究供应商，这些任务的上下文混在一起，AI 处理就会乱。

子代理把每件事**隔离开**：

- 一个"供应商研究"子代理——只研究单家供应商，只用搜索工具，返回结构化的研究简报
- 一个"规格核查"子代理——只检查报价里的规格是否符合图纸要求
- 一个"询价函生成"子代理——只生成询价函，只用 docx 技能

每个子代理范围窄、工具限定、指令固定。结果就是它做得**始终一致**。

### 子代理是配置文件

子代理就是 `.claude/agents/` 文件夹下的几个文本文件。**你写一个好的子代理一次，整个团队都能用**——把文件分享出去，每个人的 Claude Code 都能调用同一个子代理，得到同样品质的输出。

这一点很重要——它把"经验丰富的某个人的判断"封装成了"团队里任何人都能用的工具"。

### 我们设置中的注意点

子代理的"配置机制"是 Claude Code 软件层面的，不依赖具体的模型，所以在我们的 DeepSeek 后端上**也能正常运行**。

但是有一点要诚实地说清楚：Claude Code 的一些高级功能（比如**把不同子代理路由到不同 Anthropic 模型**——重活给 Opus，轻活给 Haiku）需要 Anthropic 的模型。在我们的设置里，每个子代理路由到的是我们的代理（proxy）能提供的模型。所以：**结构是稳定的（因为是配置层面），输出质量取决于背后的模型本身**。

### 它跟其他几章的关系

- 子代理是一个**"工人"**
- 它内部使用**技能**（流程/方法）和 **MCP**（工具）来完成它的专门任务
- 多个子代理组合起来工作就是下一章的**多代理编排**

## 第五章：多代理编排 — 协调多个 AI 一起干活

### 什么是多代理编排

多代理编排是指**协调多个 AI 代理一起完成一个大任务**：一个"领导"代理把任务拆成小块，分给"工人"代理（每个工人在自己的上下文里独立工作，通常是并行），最后把结果整合起来。

这个模式叫"orchestrator-workers"（编排者-工人）模式。

### 为什么需要它

有些任务太大、太多部分，让一个 AI 顺序处理太慢、上下文太挤。比如：

- 同时深入研究 10 家供应商
- 同时审核 20 份合同
- 同时分析多个市场的趋势

这些任务的特点是：**可以拆分成独立的子任务，并行处理**。编排就是干这个的。

### 一个关键的新消息：Opus 4.8 的 Dynamic Workflows

**2026 年 5 月 28 日**（也就是不久前），Anthropic 在 Claude Code 里推出了一个新功能叫 **Dynamic Workflows（动态工作流）**，目前是"研究预览版"（research preview），需要 Enterprise、Team、或 Max 计划。

它的能力是：**让 AI 自动计划一个任务，启动几百个并行的子代理同时干活，然后自动验证每个输出，最后报告给你**。

对采购研究来说，这是个量级的飞跃——以前你可能让 AI 顺序研究 5 家供应商，要等十几分钟；现在可以同时研究 50 家供应商，几分钟出结果，每份研究简报还经过自动核查。

### 老实说一下现状

多代理编排在 2026 年还是个相对新的东西，要诚实地讲一下它的局限：

- 是**实验性的**，默认是关闭的
- 没有**跨会话的记忆**——每次开始都是新的
- **可观察性有限**——你不太能看清楚每个子代理在干什么
- **成本会快速上升**——每个子代理都在消耗 token
- 在我们的 DeepSeek 后端上，**协调质量会比 Anthropic 自己的 demo 粗糙**

所以：**把它当作"未来的方向"，不是"明天就部署"**。对绝大多数日常采购工作，一个有正确技能和 MCP 工具的代理就已经够用了。多代理编排的价值在那种真的需要并行处理大批量任务的场景。

### 一个具体的采购场景

你接到一个询价任务："帮我评估一下国内 8 家钢板供应商，给我一份采购推荐。"

**没有编排时**：你逐家研究，逐家写简报，逐家比较。可能要半天。

**有编排时**：你把这个任务交给"领导代理"，它启动 8 个"供应商研究子代理"同时运行，每个研究一家，几分钟后所有简报回来，领导代理把它们整合成一份带排名的采购简报。

### 用的时候要注意什么

如果你真的开始用多代理编排，**一定要设硬限制**：

- 最大步骤数（防止它无限循环）
- 最大成本（防止 token 烧光）
- 真实测试 20-30 个案例后再上线（防止它在你没注意的时候出错）

### 它在整套体系里的位置

多代理编排坐在**最顶层**：

- 它组合**子代理**
- 子代理用**技能**和 **MCP** 工具
- 这些都跑在 **API** 调用之上

这一层最强大，也最不成熟。所以下一章——评估——尤其重要。

## 第六章：评估（Evals）— 知道 AI 是否真的在工作

### 什么是评估

**评估（eval）就是一个可重复的测试**，用来衡量 AI 的输出在一组代表性任务上是否真的正确、可靠。

简单来说：你拿过去已经知道正确答案的几十个真实任务，让现在的 AI 跑一遍，对比结果。**通过几个、失败几个，一目了然**。

### 为什么这是最重要的一章

这是这套体系里**唯一一个不可以省略**的部分。

为什么？因为 **AI 不会"崩溃"——它会自信地给你错答案**。它可能：

- 漏掉报价里的一个关键栏
- 把欧元误算成美元
- 凭空"创造"一家不存在的供应商
- 把规格里的"12mm"读成"1.2mm"

如果没有评估，**你不会发现**。你以为它在好好工作，其实它已经悄悄出错好几周了，直到某天采购单出问题。"看起来正常"不是一个可靠的衡量标准。

### 对我们的设置特别重要

我们用的是 DeepSeek 后端。这意味着两个事实：

1. DeepSeek 的行为跟 Claude 不完全一样，有些指令的遵循程度会差一些
2. 当我们的代理（proxy）升级或者 DeepSeek 发布新版本时，**行为可能在我们不知情的情况下改变**

评估是**唯一的早期预警系统**。它告诉你"昨天还在正常工作的技能，今天还在不在正常工作"。

### 怎么搭一个评估

需要三样东西：

1. **测试案例**：15-20 个真实的、过去的采购案例（报价、规格、当时的处理结果）
2. **已知正确答案**：每个案例对应的"应该长什么样"的输出（实际发出去的询价函、当时做的比较表、最终选的供应商）
3. **打分方法**：一个脚本，让 AI 用现在的技能跑每个案例，把输出和已知答案对比，给出通过/失败

跑一遍，看通过率。比如 19/20 通过——OK。哪天变成 12/20，立刻知道有东西坏了，**在它影响真实业务之前**。

### 一个具体的工作场景

你今天调整了一下"询价函生成"技能（比如改了一行格式要求）。改完之后第一件事：跑评估。

- 如果 20/20 都通过——OK，改动安全
- 如果 18/20 通过——看看哪两个失败了，可能是改动的副作用
- 如果 12/20 通过——改动有严重问题，回滚

**评估让你敢于改动**。没有评估，每次改东西都像在赌博——你不知道你刚刚是不是不小心打坏了什么。

### 评估在体系里的位置

评估**坐在所有东西下面**，是信任层。它告诉你：你的 API 调用、MCP 连接、技能、子代理、多代理编排，是不是真的在工作——还是在悄悄失败。

特别是在 DeepSeek 后端上，**评估不是可选的**——它是让所有上面这些东西能放心使用的前提。

---

## 结语：整套体系

读完六章之后，回到第一章的开头那句话——这是一套**完整的体系**，不是六个孤立的工具。回顾一下：

1. **API** 是地基。一切都跑在它之上。
2. **MCP** 给 AI 装上"手"，让它能接入工具和数据。
3. **技能** 给 AI 装上"方法"，让它按你的方式做事，结果一致。
4. **子代理** 把"特定任务的专家"包装成一个可调用的工人。
5. **多代理编排** 让多个子代理同时干活，处理大规模任务。
6. **评估** 是底层的信任系统，告诉你以上所有东西是不是真的在工作。

对我们的采购工作来说，**最先有回报的是 MCP 和技能**（让 AI 真的能读你的文件、生成真的 Word 询价函、Excel 比较表）。子代理和多代理编排是中长期的工具，特别是供应商研究这类场景。评估是**从你开始用任何上面的东西的第一天起就要建立的习惯**。
