# AI 实践实验室（Labs）

这是学习平台的"动手实验"部分。每个 Lab 对应理论里的一章——你看完视频、读了理论之后，到这里来真正用一下。

每个 Lab 都设计成可以独立完成，大约半小时到一小时。不需要写代码（除了 Lab 1 有一个十行的 Python 脚本，复制粘贴就行）。每一步都告诉你：

- **做什么**（在屏幕上点什么、打开什么）
- **给 Claude 发什么消息**（中文，可以直接复制粘贴）
- **应该看到什么**（你怎么知道这一步成功了）

如果某一步没按预期工作，往下读"如果出错了"部分。

整个 Lab 系列围绕一个真实的采购场景：**采购 50 吨 A516 Gr70 碳钢板，12mm 厚，用于储罐制造**。你会用 AI 一步步完成从询价、报价比较、供应商研究、到最终推荐的整个流程。

## Lab 1: 你的第一次 API 调用

### 目标

用一个真实的第三方 API 拿到当天的钢价。看清楚 API 到底是什么——不是抽象的概念，而是一段代码、一个端点、一段 JSON 回应。

### 准备

- 一台能上网的电脑（最好能访问国外网站；如果在公司内网，可能需要切到能访问 metals-api.com 的网络）
- 安装好 Python 3（命令行输入 `python3 --version` 能看到版本号就行）
- 大约 10 分钟

### 步骤

**第一步：注册一个免费的 API 账号**

打开浏览器，访问 **metals-api.com**，点 "Get API Key"。用邮箱注册一个免费账号。注册完成后，进入控制台（dashboard），找到你的 **API Key**，复制下来。

它看起来是一长串字母数字，类似 `abc123xyz456...`。**这就是 API key——相当于一张通行证。不要把它发给任何人，不要 commit 到 git，不要发到微信群**。

**第二步：创建一个 Python 脚本**

在你的电脑上找一个空文件夹，创建一个新文件叫 `first_api_call.py`。把下面的内容粘贴进去：

```python
import requests

API_KEY = "把你的密钥粘贴在这里"

# 调用 Metals-API 获取今天的钢价
url = f"https://metals-api.com/api/latest?access_key={API_KEY}&symbols=STEEL-HR,STEEL-RE"
response = requests.get(url)
data = response.json()

print("今天的钢价（美元）：")
print(data)
```

把 `把你的密钥粘贴在这里` 换成你刚才复制的 API key。

**第三步：跑一下**

打开命令行，进入这个文件夹，运行：

```
python3 first_api_call.py
```

你应该看到一段 JSON 数据，里面包含今天的 LME Steel HRC FOB China 价格、Steel Rebar 价格等等。**这就是一次 API 调用**——你的脚本向 metals-api.com 发了一个请求，它返回了今天的钢价数据。

**第四步：现在打开 Claude Code，做同样的事的另一种方式**

在 Claude Code 里输入这条消息：

```
我刚刚用 Metals-API 调了一个 API 拿到今天的钢价，返回了 JSON 数据。请帮我解释一下：当我跟你聊天的时候，背后是不是也在做类似的 API 调用？请用我刚才那个钢价的例子做对比说明。
```

Claude 会告诉你：是的，你跟它的每一次对话，本质上都是 Claude Code 在帮你打包一个请求、发送到 AI 模型的 API 端点、把回应给你显示。**模型也是一个 API**——同样的"请求-回应"模式，只不过模型返回的是文本，钢价 API 返回的是数据。

### 检查点

你完成 Lab 1 后应该能回答：

- API 是什么？（程序与程序对话的标准方式）
- API key 是什么？（一张通行证，保密）
- 你的 Claude Code 和 metals-api 都是 API 吗？（是的）

### 如果出错了

- 脚本报"requests 找不到"——运行 `pip install requests` 或 `pip3 install requests`
- 返回的 JSON 里有 "error" 字段——大概率是 API key 输错了或没激活
- 访问不了 metals-api.com——切换网络试试

### 延伸（可选）

试试用同样的 API 拿到铜、锌、铝的价格。把脚本里的 `symbols=STEEL-HR,STEEL-RE` 换成 `symbols=COPPER,ZINC,ALUMINUM`，再跑一遍。

## Lab 2: 给 Claude 装上"手"——MCP 实战

### 目标

亲手给 Claude Code 连接三个 MCP 工具，看它从"只能说话"变成"能做事"：能搜网、能读你的文件、能开浏览器自动操作。

### 准备

- Claude Code 安装好
- 创建一个新文件夹叫 `procurement-demo/`
- 在里面创建一个子文件夹 `quotes/`，放两三份样例报价文件进去（PDF 或 Word 都可以，没有真实的就编几个简单的）
- 大约 1 小时

### 步骤

**第一步：先看看现在连了什么——清场**

打开 Claude Code，输入：

```
/mcp
```

应该看到一个列表，告诉你当前连接了哪些 MCP 服务器。**如果你看到一些你不认识的服务器（比如 Firecrawl 或别的），先把它们移除**——为了 Lab 体验干净，我们要从"空白"开始：

```
claude mcp list
claude mcp remove <服务器名>
```

把不认识的、不需要的全部 remove 掉。再跑 `/mcp` 确认列表是空的或只剩你认识的。

**第二步：试一个 AI 现在做不到的任务**

在 Claude Code 里输入：

```
请帮我查一下今天 A516 Gr70 钢板在中国市场的 FOB 报价区间是多少？
```

它做不到——它没有上网的工具。它可能会含糊地回答"根据我的训练数据，大约是..."（用的是旧数据）或者直接说它没法查实时数据。**记住这个时刻**——这就是"没有手"的 AI。

**第三步：装一个网页搜索工具**

注册一个免费的 Brave Search API（brave.com/search/api），拿到 API key。然后在 Claude Code 里安装：

```
claude mcp add brave-search npx -y @modelcontextprotocol/server-brave-search --api-key <你的密钥>
```

再跑 `/mcp` 确认它出现了。

**第四步：再问同样的问题**

输入同样的提示：

```
请帮我查一下今天 A516 Gr70 钢板在中国市场的 FOB 报价区间是多少？
```

**这次不一样了**——你会看到 AI 调用了 brave-search 工具（屏幕上会显示工具调用），然后返回真实的、当前的搜索结果，包含真实的报价区间。**这就是"装上手"的 AI**。

**第五步：装一个文件系统工具**

让 AI 能读你 `quotes/` 文件夹里的报价：

```
claude mcp add filesystem npx -y @modelcontextprotocol/server-filesystem ./quotes
```

注意我们**只给它一个文件夹的权限**——不是整个硬盘。**最小权限原则**。

再跑 `/mcp` 确认它装好了。

**第六步：让 AI 读你的报价文件**

输入：

```
请读取 quotes 文件夹里的所有报价文件，告诉我每家供应商的报价、币种、交货期。
```

应该看到 AI 调用文件系统工具，读取文件，整理出一份对比信息。

**第七步：装一个浏览器自动化工具**

```
claude mcp add playwright npx -y @modelcontextprotocol/server-playwright
```

然后给它一个任务：

```
请打开 1688.com，搜索"A516 钢板"，列出前三个搜索结果的供应商名字和报价范围。
```

你会看到 AI 启动了一个浏览器（也许是看不见的"无头浏览器"），导航到 1688，搜索，提取数据。**这是它能去任何网站上"操作"的能力**。

### 检查点

完成 Lab 2 后你应该：

- 能回答"什么是 MCP"——一个标准接口让 AI 连接到外部工具
- 知道至少三种工具：搜索、文件系统、浏览器自动化
- 看到了"没有 MCP 的 AI"和"有 MCP 的 AI"的区别

### 如果出错了

- `claude mcp add` 命令报错——确认你的 Claude Code 版本支持这个命令，可能需要更新
- 工具装了但 AI 不调用——明确告诉它"请用 brave-search 工具查询..."
- 浏览器自动化失败——Playwright 第一次安装会下载浏览器，要等一下

### 延伸（可选）

试着同时连五六个工具，然后让 AI 做一个组合任务（比如"读取报价文件，搜索市场行情，告诉我哪家供应商的报价偏高"）。看看 AI 怎么决定用哪些工具。

## Lab 3: 用 Claude 制作真实文档——Skills 实战

### 目标

安装 Anthropic 官方的 docx 和 xlsx 技能，让 Claude 真的能给你生成可以发给供应商的 Word 询价函和一份带公式的 Excel 比较表。

### 准备

- Lab 2 的 `procurement-demo/` 文件夹还在
- 安装了 git（命令行能跑 `git --version`）
- 大约 45 分钟

### 步骤

**第一步：克隆官方技能仓库**

打开命令行，跑：

```
git clone https://github.com/anthropics/skills /tmp/anthropic-skills
```

这会把 Anthropic 公开的所有官方技能下载到 `/tmp/anthropic-skills/`。

**第二步：把需要的技能拷贝到你的项目**

进入你的 `procurement-demo/` 文件夹，创建一个隐藏的 `.claude/skills/` 文件夹：

```
cd procurement-demo
mkdir -p .claude/skills
cp -r /tmp/anthropic-skills/skills/docx .claude/skills/
cp -r /tmp/anthropic-skills/skills/xlsx .claude/skills/
cp -r /tmp/anthropic-skills/skills/pdf .claude/skills/
```

**第三步：在 Claude Code 里确认技能加载了**

重启 Claude Code（关掉再打开），在 `procurement-demo/` 文件夹下打开它。然后随便问一下：

```
你现在有哪些技能可用？请列出来。
```

你应该看到 docx、xlsx、pdf 在列表里。

**第四步：用 docx 技能生成一份中文询价函**

输入：

```
请用 docx 技能，给江苏宝武钢材有限公司生成一份正式的中文询价函 Word 文档。

需求：
- 材料：A516 Gr70 碳钢板，厚度 12mm
- 数量：50 吨
- 交货地：上海港
- 要求供应商提供：单价（人民币）、交货期、国际贸易术语、付款条件
- 我方公司名称：[你的公司名]
- 落款人：采购部 张经理

文件保存在 procurement-demo 文件夹下，命名为 RFQ-江苏宝武-A516.docx
```

等几秒钟，Claude 会调用 docx 技能里的脚本，生成一个真实的 .docx 文件。

**第五步：打开生成的文件**

用 Word 或者 WPS 打开 `RFQ-江苏宝武-A516.docx`。你看到的应该是：

- 真实的 Word 文档格式
- 中文内容、规范的询价函结构
- 标题、抬头、正文、落款都整齐

**这就是技能的力量**——AI 不是只输出了一段文字，而是生成了一份**可以直接发给供应商的文件**。

**第六步：用 xlsx 技能生成报价比较表**

假设你已经收到了三家供应商的报价（如果你的 `quotes/` 文件夹里有三份，更好；如果没有，下面的提示里编三家假数据）：

```
请用 xlsx 技能创建一份报价比较 Excel 表，对比这三家供应商：

供应商 A：江苏宝武钢材有限公司，单价 4500 CNY/吨，交货期 30 天，FOB 上海
供应商 B：Mumbai Steel Trading Co，单价 580 USD/吨，交货期 45 天，CIF 上海
供应商 C：Rotterdam Metals BV，单价 540 EUR/吨，交货期 21 天，FOB 鹿特丹

数量都是 50 吨。

表格要求：
- 列：供应商、单价（原币种）、币种、汇率、单价（CNY）、交货天数、国际贸易术语、50 吨总金额（CNY）
- 汇率请用今天的近似汇率（USD≈7.2 CNY，EUR≈7.8 CNY），写在专门的栏里
- 所有 CNY 转换和总金额必须用真实的 Excel 公式计算，不要硬编码
- 最后加一行"推荐"列，根据综合（价格 + 交货期）给出推荐

文件保存为 报价比较表-A516.xlsx
```

**第七步：打开 Excel 文件**

用 Excel 或 WPS 打开 `报价比较表-A516.xlsx`。点击任何一个"单价（CNY）"或"总金额"的格子——你会看到它是**真的 Excel 公式**（像 `=C2*D2` 这种），不是硬编码的数字。

这意味着如果你改一下汇率，所有依赖那个汇率的数字会**自动重新计算**。

**第八步：再跑一次同样的提示，看一致性**

把第四步那条"生成询价函"的提示**原封不动**再发一遍（换一家供应商名字也行）。新生成的文件应该有**完全一样的格式结构**——这就是技能的核心价值：**一致性**。

### 检查点

完成 Lab 3 后你应该：

- 能解释技能（Skill）是什么——AI 的"标准操作手册" + 可能的脚本
- 看到了真实的 Word/Excel 文件从 AI 出来
- 理解了为什么"把精确逻辑放在脚本里"（脚本不依赖模型，确定性产出）

### 如果出错了

- git clone 失败——检查网络；或者直接从 GitHub 网页下载 zip
- Claude 说找不到 docx 技能——检查 `.claude/skills/docx/SKILL.md` 文件存在；重启 Claude Code
- 生成的 .docx 格式乱码——确认你的系统支持中文字体（一般 Word/WPS 都行）

### 延伸（可选）

试试用 pdf 技能填充一份固定格式的供应商资质核查表——给 PDF 模板，让 AI 填上信息。

## Lab 4: 创建一个供应商研究专家——子代理实战

### 目标

创建一个"供应商研究"子代理，让它去深入研究一家真实的中国钢铁供应商，返回结构化的研究简报。然后调用它研究第二家、第三家，看每份简报的结构都一样。

### 准备

- Lab 3 完成（`.claude/` 文件夹存在）
- Lab 2 的 brave-search 或其他搜索工具仍然连接着
- 大约 45 分钟

### 步骤

**第一步：创建子代理配置文件**

在 `procurement-demo/.claude/agents/` 文件夹下（如果没有就创建一下），创建一个新文件叫 `supplier-researcher.md`。把下面的内容粘贴进去（这是子代理的"指令书"）：

```markdown
---
name: supplier-researcher
description: 研究单家供应商，返回结构化的研究简报。当被要求"研究"、"调查"、"评估"某家具体的供应商时使用。
tools: [web_search, web_fetch, read_file]
---

你是一名为工业储罐制造企业服务的供应商研究专员。给定一个供应商名字，请去深入研究他们，按以下结构返回一份中文研究简报（每个小节都要有）：

## 公司背景
成立年份、总部、规模、所有制（国企/民营/外资）、主要市场。

## 制造能力
主要产能、工厂位置、典型交货期、出口经验、可生产的钢材规格。

## 资质认证
ISO、ASTM、EN、ASME 等。特别关注压力容器相关认证。如果发现某项认证有过期或可疑迹象，要注明。

## 近期动态
过去 12 个月内的：扩产、纠纷、质量事件、领导层变动、制裁、财务问题。

## 风险信号
合规、财务、声誉、运营层面的风险。具体说明——没发现就写"公开渠道未发现明显风险信号"。

## 价格定位
高端 / 中端 / 低端，基于公开可观察的信息。如果他们公开的价格与同行明显偏离，请指出。

要求：
- 简报控制在一页以内
- 如果某一节找不到信息，写"公开渠道未找到"——不要编造
- 关于动态、认证、风险的具体说法，请注明信息来源
```

保存。

**第二步：确认子代理被识别**

在 Claude Code 里输入：

```
/agents
```

你应该看到 `supplier-researcher` 出现在列表里。

**第三步：调用它研究第一家供应商**

```
请调用 supplier-researcher 子代理，深入研究这家供应商：宝武钢铁集团。
```

子代理会在它**自己的上下文**里运行——它会做搜索、读取网页、汇总信息，然后返回那份结构化的简报。中文输出，按你定义的小节排列。

**第四步：调用它研究第二家**

```
请调用 supplier-researcher 子代理，深入研究这家供应商：沙钢集团。
```

第二份简报会按**完全一样的结构**回来，但内容是沙钢的。

**第五步：再来一家**

```
请调用 supplier-researcher 子代理，深入研究这家供应商：河钢集团。
```

现在你有了三份简报，结构相同，可以直接比较。

**第六步：让主代理整合三份简报**

```
我刚才让 supplier-researcher 研究了三家：宝武钢铁、沙钢、河钢。请基于这三份简报，从我们的"采购 A516 Gr70 钢板"的需求角度出发，给我一个简短的对比总结，指出每家的强项和弱项。
```

注意——这一步**不是子代理**，是主代理做综合。子代理负责"研究单家"，主代理负责"做决策类的综合"。

### 检查点

完成 Lab 4 后你应该：

- 能解释子代理是什么——一个专门做某件事的、配置可重用的助手
- 看到了同一个子代理输出的三份简报，结构完全一致
- 理解"专门化 + 隔离上下文"为什么让结果更稳定

### 如果出错了

- /agents 看不到 supplier-researcher——检查文件路径是 `.claude/agents/supplier-researcher.md` 而不是别的；重启 Claude Code
- 子代理输出格式飘了——它的指令可能不够明确；回到 SKILL.md 加一句"请严格按上述六个小节输出，每节都要有"
- 子代理找不到信息——可能 brave-search 没连接；跑 `/mcp` 确认

### 延伸（可选）

再创建一个 `spec-checker` 子代理——专门检查供应商报价里的规格是否符合一份给定的图纸/规格书要求。配置文件结构跟 supplier-researcher 一样，只是工具和提示不同。

## Lab 5: 让多个 AI 一起干活——多代理编排实战

### 目标

体验多代理编排——同时研究多家供应商，把结果整合成一份采购推荐。**这是这套 Lab 里最前沿、最不成熟的一个，所以也要诚实地看到它的局限**。

### 准备

- Lab 4 完成（supplier-researcher 子代理可用）
- **分情况**：
  - **路径 A**（你有 Opus 4.8 + Dynamic Workflows 访问权——需要 Enterprise/Team/Max 计划）——可以体验完整版
  - **路径 B**（没有的话）——做小规模版本 + 看看 Anthropic 的发布页了解前沿到哪里了
- 大约 1 小时

### 路径 A：Dynamic Workflows 完整版

**第一步：确认 Opus 4.8 和 Dynamic Workflows 启用**

在 Claude Code 模型选择器里切到 **Opus 4.8**。在设置里启用 **Dynamic Workflows**（研究预览版功能，可能需要在 settings 里找一下）。

**第二步：给它一个真正"大"的任务**

```
请深入研究以下 8 家中国钢铁供应商，对每一家返回：公司背景、产能、压力容器相关认证、近 12 个月动态、风险信号。然后基于这些研究，结合我们要采购 50 吨 A516 Gr70 钢板（12mm 厚）用于储罐制造的需求，输出一份一页的采购简报，把这 8 家按推荐顺序排名。

供应商名单：
1. 宝武钢铁集团
2. 沙钢集团
3. 河钢集团
4. 鞍钢集团
5. 首钢集团
6. 山东钢铁集团
7. 江苏沙钢
8. 太钢不锈
```

**第三步：观察它的工作过程**

你应该看到：

1. **规划阶段**——Claude 先列出怎么拆这个任务
2. **并行执行**——多个子代理同时启动，每个研究一家
3. **验证阶段**——Claude 检查每份简报的质量
4. **整合阶段**——所有简报合并成最终的采购推荐

整个过程可能 5-10 分钟，比顺序做（45 分钟以上）快多了。

### 路径 B：用现有工具做小规模版本

**第一步：让主代理顺序调用子代理**

```
请帮我做这件事：依次调用 supplier-researcher 子代理研究这三家：宝武钢铁、沙钢、河钢。每家研究完之后等下一家。三家都研究完之后，基于我们要采购 50 吨 A516 Gr70 钢板用于储罐制造的需求，输出一份采购推荐简报，对三家做对比排名。
```

**第二步：观察过程**

主代理会依次调用 supplier-researcher，三份简报回来，然后综合。**这是"顺序"版本——不是真正的并行，但思路一样**：拆分 → 委派 → 整合。

**第三步：去看看真正的并行长什么样**

打开浏览器，访问：

```
https://www.anthropic.com/news/claude-opus-4-8
```

读一下 Dynamic Workflows 的介绍。看它能做什么：**几百个并行子代理在一个 session 里**，自动规划、自动验证、自动整合。

这是**前沿在哪里**。我们今天用的小规模版本是同一个模式的小号版。等我们的设置支持 Opus 4.8（或者我们升级到 Anthropic 直连的方案）时，这就是开箱即用的能力。

### 一个重要的纪律

## Lab 6: 建立信任——评估你的 AI 系统

### 目标

搭一个小型评估系统，看评估**真的能抓出问题**——故意打破一个技能，让评估帮你发现。

### 准备

- Lab 3 完成（docx 和 xlsx 技能可用）
- 收集 3-5 份**已经处理完的过去采购案例**（已经确定的报价、已经选定的供应商、当时实际做出的比较表）
- 大约 45 分钟

### 步骤

**第一步：搭建 evals 文件夹结构**

在 `procurement-demo/` 下创建：

```
evals/
├── case-01/
│   ├── inputs/                  # 当时收到的报价文件
│   ├── expected.json            # 这个案例的"标准答案"
├── case-02/
│   ├── inputs/
│   ├── expected.json
└── ... (case-03 至 case-05)
```

**第二步：给每个 case 写 expected.json**

每个 `expected.json` 描述这个案例的"对的输出应该长什么样"。比如 case-01：

```json
{
  "材料": "A516 Gr70 钢板",
  "数量": {"值": 50, "单位": "吨"},
  "厚度": "12mm",
  "应包含的字段": ["供应商", "单价", "币种", "USD换算单价", "交货天数", "贸易术语", "总金额"],
  "应使用的公式": ["USD换算", "总金额"],
  "最终选定供应商": "江苏宝武钢材有限公司",
  "选定理由": "单价最低 + 交货期 30 天可接受"
}
```

为剩余 case 写类似的 JSON。

**第三步：写一个评估脚本**

在 `procurement-demo/scripts/run_evals.py` 里写：

```python
import json
import os
from pathlib import Path

EVALS_DIR = Path("evals")
PASSED = 0
FAILED = 0
FAIL_DETAILS = []

for case_dir in sorted(EVALS_DIR.iterdir()):
    if not case_dir.is_dir():
        continue

    expected_path = case_dir / "expected.json"
    with open(expected_path, "r", encoding="utf-8") as f:
        expected = json.load(f)

    # 这里是关键 ——
    # 在真实评估里，你会让 Claude 用现在的 docx/xlsx 技能跑这个 case 的输入，
    # 然后用 python-docx 和 openpyxl 提取生成文件里的字段，跟 expected 对比。
    #
    # 为了 Lab 简单，我们用一个占位符函数 run_skill_on_case(case_dir)
    # 你可以先返回一个手动构造的"假"结果，验证评估框架本身能跑

    # 占位符：手动指定一个结果用于测试
    actual = {
        "材料": "A516 Gr70 钢板",
        "数量": {"值": 50, "单位": "吨"},
        "应包含的字段": ["供应商", "单价", "币种", "USD换算单价", "交货天数", "贸易术语", "总金额"],
        "最终选定供应商": "江苏宝武钢材有限公司",
    }

    # 简单对比：检查所有应包含字段都在
    expected_fields = set(expected["应包含的字段"])
    actual_fields = set(actual.get("应包含的字段", []))
    missing = expected_fields - actual_fields

    if not missing and actual.get("最终选定供应商") == expected.get("最终选定供应商"):
        PASSED += 1
        print(f"✅ {case_dir.name}: PASS")
    else:
        FAILED += 1
        FAIL_DETAILS.append(f"{case_dir.name}: missing fields {missing}, supplier match: {actual.get('最终选定供应商')==expected.get('最终选定供应商')}")
        print(f"❌ {case_dir.name}: FAIL — missing: {missing}")

print(f"\n总结: {PASSED}/{PASSED + FAILED} 通过")
if FAIL_DETAILS:
    print("失败详情：")
    for d in FAIL_DETAILS:
        print(f"  - {d}")
```

**第四步：跑评估**

```
python3 scripts/run_evals.py
```

应该看到所有 case 都通过：`5/5 通过`。

**第五步：故意打破一个技能**

现在玩一下——故意制造一个 bug，看评估能不能抓住。

打开 `.claude/skills/xlsx/SKILL.md`，找到关于"包含的列"或者"使用公式"的指令，**删掉其中一条**或改一下。保存。

或者更简单——直接改 `run_evals.py` 里那个占位符，让它返回少一个字段的结果：

```python
"应包含的字段": ["供应商", "单价", "币种", "交货天数"],  # 少了 USD换算单价、贸易术语、总金额
```

**第六步：再跑一遍**

```
python3 scripts/run_evals.py
```

这次应该看到失败——评估抓住了缺失的字段：`2/5 通过`。**这就是评估的核心价值**——它告诉你"有东西不对"，**在它跑到真实采购单之前**。

**第七步：修复**

把刚才的改动还原。再跑一遍。应该恢复 `5/5 通过`。

### 检查点

完成 Lab 6 后你应该：

- 能解释什么是评估——一个让你知道 AI 真的没坏掉的测试系统
